# ab100 受控实验归档

100 条样本（50 条原失败 + 50 条原成功，seed 20261019），**冻结 L1 起点**，
用于比较「L2 侧干预」与「认块并行方案」。

## 为什么必须冻结 L1

早期两次 A/B 都被污染过：

1. **拿历史结果当对照** → 选择性偏差：新跑一次对照组，自己就修好了 8/50
2. **两条臂各自重新采样 L1** → 起点差异最大到 1859px

`--l1-box-file` 把 L1 的框冻结成数据（`l1box.json`），两条臂从同一个框起跑。

## 结果总表

| 变体 | 命中 | 原失败 50 | 原成功 50 | 单次 | 结论 |
|---|---|---|---|---|---|
| 对照 legacy | 57 | 8/50 | 49/50 | 7.8s | 基线 |
| describe-first | 58 | 9/50 | 49/50 | 9.8s | 无效 |
| 反转阶梯 | 49 | 15/50 | 34/50 | 13.1s | 代价太大 |
| strict-notvis | 63 | 15/50 | 48/50 | 5.8s | +6pp（不显著）|
| out-px 1600 | 63 | 15/50 | 48/50 | 5.5s | +6pp（**M3 未复现**）|
| blurry | 60 | 13/50 | 47/50 | 7.6s | +3pp |
| **认块 + 双块并行 + 置信度（top-3）** | **71** | **27/50** | 44/50 | 3.2min/100 | **+14pp，p≈0.0106** |
| **↑ 再加对冲早退（conf≥90、12s 窗口）** | **74** | **28/50** | 46/50 | 4.0min/100 | **+17pp，p≈0.0016** |

⚠️ **只有最后一行显著。** 前面几行都是 +3～6pp，落在 n=100 的噪声区间内
（n=100 只能可靠检出 ≥10pp）。`out-px 1600` 已在 M3 全量（1261 条）上被证伪：
83.2% → 83.7%，p≈0.53。

## 认块方案的关键数字

| 项 | 数值 |
|---|---|
| 认块召回 top-1 / top-2 / top-3（**none** 思考）| 83% / 93% / **96%** |
| 认块召回 top-1 / top-2 / top-3（high 思考）| 91% / 97% / 97% |
| 任一块命中（天花板）| 79/100 |
| 择优命中 | 71/100 |
| **块内框误差（命中样本）** | **1–6px**（整屏流程为 20px）|
| 100 条耗时（10 并发）| 3 分 13 秒 |

**认块用 `none`**：top-2 只差 4pp，但 32 秒 vs 13 分钟。

**块内精度是关键发现**：块是整屏的 1/3，目标大 3 倍，模型「直接指」的误差从 20px 降到 1–6px。
它缺的不是分辨率，是**坐标换算**能力——所以认块与指位置必须拆开。

## 对冲早退（`--early-exit 90 --hedge-ms 12000`）

先只发 rank1；它在 12 秒内回来且自报置信度 ≥90 就直接采用，其余两块**根本不发**；
否则再并行补发其余块。

| | 全量三块 | **对冲早退** |
|---|---|---|
| 命中 | 71/100 | **74/100** |
| 单条延迟中位 | 20.4s | **11.8s** |
| 平均跑几块 | 3.00 | **1.74** |
| 早退样例 | — | 63 条，延迟 9.6s，命中 86% |
| 未早退样例 | — | 37 条，延迟 32.4s |
| 批处理（100 条 / 10 并发）| 193s | 242s ✗ |

**精度反而升 3 条**：早退跳过了错误的候选块，减少了「置信度倒挂选错」的机会。

**批处理变慢是取舍**：37 条未早退的样例各占一个 worker 32 秒。**加并发数可解**
（10 → 20 worker 约 121s，未实测）。

**试过但否决的排法**：三块全发 + 自信后取消其余。
单条延迟 15.6s（更差——30 个调用同时在飞，把 rank1 自己也拖慢了）、命中 72（更低），
只有批处理 205s 更好。

## 描述字段消融：两个"改进"都被证伪

认块包装器手拼描述时与官方 `desc_lines` 有两处差异：**带「屏幕位置」**、**漏「周边锚点」**。
两处看起来都像 bug，实测**两个都不能改**。

### 24 条诊断集（11 条被切块弄坏 + 13 条被切块救回）

| 组 | 描述 | 命中 | 任一块 |
|---|---|---|---|
| A | qwen 描述（默认）| 13/24 | 16/24 |
| B | 去「屏幕位置」| 12/24 | 14/24 |
| C | 去位置 + 加锚点 | **17/24** | 19/24 |
| D | DS 自己写描述 | 15/24 | 17/24 |

C 组看起来 +4，于是上 100 条验证——**结果翻成 −9**。

### 100 条全量（配对）

| 组 | 命中 | 任一块 | 结论 |
|---|---|---|---|
| **基线（有位置、无锚点）** | **74** | **79** | **最优** |
| 只加锚点 | 69 | 78 | −5 |
| 只去位置 | **61** | 67 | **−13** |
| 两者都改 | 65 | 74 | −9 |

### 为什么

**「屏幕位置」是认块的有效线索，不是干扰项。**
认块问的是"目标在哪一块"，而「屏幕水平中部、垂直正中」能直接映射到 3×3 网格的中间格——
它描述的是**原图**上的位置，而认块正是在**原图**网格里选块，语义完全对齐。

**「周边锚点」对认块是噪声。** 锚点（"某按钮右边"）服务于精确指位置，
认块只需要"大概在哪一块"，多余细节反而干扰。

### 教训

24 条样本的置信区间约 ±15pp，+4 完全在噪声内。
**这是第二次同类错误**（上一次是 n=100 的 `--out-px` +6pp 在 M3 全量上消失）。
小样本只能用来排除大效应，不能用来确认小收益。

### 顺带修掉的真 bug

DS 后端的描述生成一直产出空字符串：生成脚本没传 `reasoning_effort`，
DS 默认会思考，`max_tokens=200` 全被思考内容吃掉，正文为空。
已加 `--reasoning-effort`（默认 `none`）并透传到 `ask_image` / `chat`。

## 择优规则（当前实现）

```python
key  = lambda r: r["conf"] if r.get("conf") is not None else -1
best = max(ok_runs, key=key)      # 平手时取排在前面的（认块排序更高）
```

`conf` = `done()` 时模型自报的 0–100 把握；**没 done 记 −1，永远不赢**。

**择优丢掉的 8 条**：

| 原因 | 条数 |
|---|---|
| 置信度倒挂（错块报得更高）| 4 |
| 平手取错 | 2 |
| 正确块没 done 被 −1 杀掉 | 2（其中 1 条三块都没 done）|

**置信度本身不是随机**：多块都 done 时按置信度选对 68%，
但**三块全都 done 时退化到 52%**。

## 待办：5 种替代择优判据（**不需要重跑，离线算**）

- **A.** 没 done 记 50 而非 −1
- **B.** 平手比框大小（取更小的）
- **C.** 平手比 move 数（取更少的）
- **D.** `conf + 5×(3−rank)` 加权
- **E.** 阈值法：rank1 的 conf ≥ 90 直接用，否则再看后面

## 复现

```bash
cd benchmarks/screenspot_grid
export QW_BASE=... QW_KEY=... QW_MODEL=qwen3.8-flash     # 凭证不落仓库

# 对照（legacy）：10 分片，每片 10 条
for i in $(seq 1 10); do
  IDS=$(sed -n "$(( (i-1)*10+1 )),$(( i*10 ))p" experiments/ab100/ids.txt | paste -sd,)
  python3 -u baselines/b3_crop_ladder.py --ids "$IDS" --split M3 \
    --backend qwen --desc-version v2 \
    --l1-box-file experiments/ab100/l1box.json \
    --tag b3_ab100_ctrl_M3_v2_q38_s$i &
done; wait

# 认块链路
python3 scripts/tile_pipeline.py --ids-file experiments/ab100/ids.txt \
  --top-k 3 --workers 10 --out /tmp/tile_top3.jsonl
```

## 跨后端：机制只对 qwen 有效

同 100 条、同冻结 L1：

| 后端 | 对照 | 认块链路 | 提升 |
|---|---|---|---|
| qwen | 57 | **74** | **+17**（p≈0.0016）|
| deepseek | **64** | 63 | −1（p≈0.84）|

诊断：DS 的单块命中率 **35%**（qwen 47%），认块召回 66/83/90（qwen 81/89/95）。
DS 整屏比 qwen 强，但**换到放大的局部图上反而变差**——它缺「局部重定位」能力。

**「模型会看不会换算」这个结论是 qwen 特有的，不是通用规律。**
