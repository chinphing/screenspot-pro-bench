## 一、本轮目标

把 DeepSeek 从"一次看图给答案"改造成**多轮工具调用智能体**：
- 单张图 token 上限只有 1008（≈1300×1300），小目标看不清
- 但它单轮只要 ~0.7 秒 → 允许它**主动要求放大**，多次处理

---

## 二、最终架构（`ds_agent3o.py`）

```
第 1 轮：送完整原图（长边 1700px，吃满 1008 token）
   ↓
每轮模型三选一：
   A. zoom(x, y)   —— 以该点为中心裁一块放大
                      · 坐标用【原图】归一化 0-1000
                      · 裁片 = 当前画面的 1/2 长宽（无像素上限）
                      · 裁片统一放大到长边 1700px
   B. back()       —— 回退上一层（历史对话不动，只把上层图重新放到最新位置）
   C. 直接输出 bbox —— 用【原图】归一化坐标
   ↓
最多 5 轮；末轮不提供工具 + 追加强制指令 → 必须作答
```

**关键设计**：
| 项 | 值 |
|---|---|
| 送图尺寸 | 每层统一长边 **1700px**（≈1.7Mpx，正好吃满 1008 token） |
| 裁片比例 | 当前画面的 **1/2 长宽** |
| 坐标系统 | **一律原图归一化 0-1000**（模型给点、模型给答案，代码不做反推） |
| 轮数上限 | 5 |
| 思考模式 | 参数 `--reasoning-effort`，实测 **none 最好** |
| 末轮 | `--force-answer-last`：不给工具 + 强制指令 |

## 四、⭐ 五条关键经验（按价值排序）

### ① 模型对"坐标相对哪张图"有极强先验，别跟它对抗

**我明确写了"用当前画面的坐标，不用换算成原图"，它 17/28 次仍然给原图坐标。**

| 坐标系约定 | 命中 |
|---|---|
| 强迫模型说"当前画面"坐标，代码反推 | **17%** ❌ |
| 让模型一直说"原图"坐标，代码不换算 | **60%** ✅ |

**→ 证据**：`vscode_macos_45` 5 次运行末层分别是 3/2/3/1/3，但两次不同层级的答案都是 `(284,66)`——**答案与所在层级无关**，证明它一直在用原图坐标系。

**→ 教训：不是所有"确定性计算"都能从模型手里拿走。当模型对某表示有强先验时，顺着它反而更好。**

### ② 模型主动说"看不清要放大"时，必须给它足够分辨率的图

**v1 里裁片"原分辨率直接送"（不放大）→ 小裁片只用了 token 预算的 1%：**

| 裁片原尺寸 | 像素 | 实际 token | 占 1008 上限 |
|---|---|---|---|
| 230×83 | 0.019 Mpx | **~11** | **1%** |
| 1152×130 | 0.15 Mpx | ~90 | 9% |

**改成统一放大到 1700px 后：30% → 60%。**

### ③ 每一层都要吃满 token 上限

**我一度把"所有层"（含原图）都压到 1200px 长边：**

| 每层尺寸 | 命中 |
|---|---|
| 1200px（0.81Mpx，~483 token） | **6%** |
| 1700px（1.7Mpx，1008 token） | **22%** |

### ④ 方向/区域的语义要和模型的自然理解一致

**我把"左"实现成"左中"（x[0,500] y[250,750]），模型理解成"整条左边"（全高）→ 方向正确率只有 40%。**

**改成"某一维取一半、另一维取满"后 → 72%。**

| 方向 | 正确语义 | 正确率 |
|---|---|---|
| 上 | x 全宽，y 上半 | **89%** |
| 左 | x 左半，y 全高 | **100%** |
| 右 | x 右半，y 全高 | **100%** |
| **中** | 两个轴都切 | **50%**（会切掉边缘目标） |

### ⑤ 离散化方向**不如**自由给坐标

| 缩放方式 | 命中 |
|---|---|
| 自由给 bbox（v1） | 60% |
| 5 方向离散（v2，修正语义后） | 17% |
| **自由给中心点 + 固定 1/2 裁剪（v3o）** | **63%** |

**→ 离散方向让模型失去"精确指向"能力，而这是它的强项。**

## 五、DeepSeek 能力边界（前一轮归档的补充）

| 结论 | 数据 |
|---|---|
| 单图 token 上限 | **1008**（≈1300×1300），≥1.7Mpx 即吃满 |
| `detail` 字段 | `low` 生效；`original`/`high`/默认**完全相同**，绕不过缩放 |
| 思考模式（单图定位） | **有害**：5/6 → 0/6，且慢 20 倍 |
| 思考模式（多图换算） | 必需，但慢 20 倍 |
| 加复杂指令 | **有害**：加"完整框住元素"要求 → 60%→47% |
| 输出框大小 | 系统性偏小，宽高中位只有真值的 **0.7× / 0.6×** |
| 与 Qwen 精度差 | 全量 20 条：DS 70% vs Qwen 81%（单轮+循环口径） |

## 六、已排除的方案

| 方案 | 结论 |
|---|---|
| 原图 + 3×3 九宫格切图（10 张图） | ❌ 补了像素尺寸与公式、开了思考也只打平，慢 20 倍 |
| 5 方向离散缩放 | ❌ 17%（修正语义后仍差） |
| 网格线叠加 | ❌ 网格 200px 比模型精度（14px）粗太多，且遮挡 UI |
| qwen3.8-max 做锚点校验 | ❌ 会把正确锚点改错 |
| DeepSeek 开思考做单图定位 | ❌ 5/6 → 0/6 |
| 提示词要求"完整框住元素" | ❌ 框大小没变，命中反而 60%→47% |

## 九、复现命令

```bash
cd benchmarks/screenspot_grid
. /tmp/ds.env          # DS_KEY / DS_BASE（必须 https://api.deepseek.com/v1）
IDS="android_studio_macos_69,fruitloops_windows_50,vivado_windows_79,\
pycharm_macos_1,origin_windows_1,vscode_macos_45"
python3 -u ds_agent3o.py --ids "$IDS" --force-answer-last \
    --desc-file results/l1/tightcrop/descriptions_v7.json --tag test
```

**主要参数**：`--max-turns 5`、`--crop-side 1700`、`--crop-cap 850`、`--reasoning-effort none`、`--force-answer-last`

## 十、环境备注

- 凭据：`/tmp/qw.env`（Qwen）、`/tmp/ds.env`（DeepSeek），mode 600，不在工作区
- **`DS_BASE` 必须为 `https://api.deepseek.com/v1`**（曾误设阿里云端点，导致大量假 401）
- DeepSeek 端点曾出现服务端过载（503 Service is too busy），与客户端无关
- 判定口径统一为**"最终框中心是否落在真值框内"**（ScreenSpot-Pro 标准）
