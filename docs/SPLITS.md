# ScreenSpot-Pro 评测集划分（M1 / M2 / M3）

> 生成时间：2026-10-16
> 数据集：`likaixin/ScreenSpot-Pro`（本地 1581 条，26 个应用）
> 划分文件：`results/splits_M1M2M3.json`、`/tmp/M1.txt`、`/tmp/M2.txt`、`/tmp/M3.txt`

## 一、划分结果

| 集合 | 条数 | 用途 | 说明 |
|---|---|---|---|
| **M1** | **20** | 开发/迭代集 | 前序所有实验（Z4/Z6/ZB/ZC/ZD/ZE/ZF 等）都在这个集合上做的；提示词调优也基于它 |
| **M2** | **100** | 筛选集 | = `experiments/ab100` 的冻结集合（50 条原失败 + 50 条原成功）；**从未用于调参**，用于快速筛方案 |
| **M3** | **1461** | 定成绩 / 留出集 | 其余全部，含旧 M2 的 300 条；最终验收用 |
| 合计 | **1581** | | 20 + 100 + 1461 = 1581 ✓ |

**互斥性**：M1∩M2 = 0，M2∩M3 = 0，M1∩M3 = 0。

> **2026-10-23 调整**：M2 由「300 条分层抽样」换成 ab100 的 100 条。
> 原因是对比实验跑不动——300 条 × 30s × 两臂要 5 小时，迭代一轮太慢；
> ab100 刻意放大方案差异，适合快速筛。**代价是它的绝对命中率不代表自然分布
> （ab100 失败率 50%，真实约 17%），所以最终成绩仍以 M3 为准。**
> 旧 M2 的 300 条没有丢，全部并入 M3；旧划分备份在 `splits/_legacy/`。

## 二、M2 构造方法（可复现）

```
来源：experiments/ab100/ids.txt（冻结文件，100 个 id）
构成：50 条「B3 原失败」+ 50 条「B3 原成功」
随机种子：20261019
排除：M1 的 20 条（交集已校验为 0）
```

**它不是随机抽样，是受控实验集。** 一半样本来自 B3 原本就失败的 case，
目的不是估计自然分布下的命中率，而是**放大方案之间的差异**——
随机抽 100 条的话，成功率 83% 意味着只有 17 条能体现改进，噪声淹没信号。

**复现**：`python3 scripts/make_splits.py`（读 `experiments/ab100/ids.txt` 写 `splits/M2.json`）。

## 三、M2 与全量的分布对比

⚠️ **ab100 的分布刻意偏离全量**，这正是它的用途；不要拿它的命中率外推。

| 维度 | 全量 1581 | ab100 100 | 偏差 |
|---|---|---|---|
| **目标尺寸** | | | |
| 小 (<40px) | 569 (36.0%) | 48 (48.0%) | **+12.0pp** |
| 中 (40–120px) | 551 (34.9%) | 28 (28.0%) | −6.9pp |
| 大 (>120px) | 461 (29.2%) | 24 (24.0%) | −5.2pp |

**ab100 偏难：小目标占 48%，全量只有 36%。** 这是构造出来的——小目标本来就是
B3 失败的主因，所以「原失败 50 条」自然向小目标倾斜。

**关键偏差**：ab100 的失败率是 **50%**，全量真实失败率约 **17%**。
所以 ab100 上 80% ≠ 全量 80%——前者是「难样本里做对八成」，后者是「随机样本里做对八成」。

**M2 的用途是排序，不是报分。**

## 四、⚠️ M1 的偏差（为什么不能拿 M1 的成绩外推）

| 维度 | M1 20 条 | 全量 1581 |
|---|---|---|
| 目标长边中位 | **40px** | 63px |
| 小目标(<40px) 占比 | **50%** | 36% |

**→ M1 明显偏难。M1 上 82% 的成绩不能当作全量成绩。**

## 五、评测协议

| 阶段 | 用哪个集 | 说明 |
|---|---|---|
| 方案迭代/调参 | **M1** | 允许反复试错；提示词/机制都在这里调 |
| 方案定成绩 | **M2** | 一旦方案冻结，在 M2 上跑；**不许回头用 M2 调参** |
| 最终验收 | **M3** | M2 定稿后一次性验收 |

**报告口径**：任何全量成绩都必须用 `eval_full.py` 报告（含命中率 + 落点质量 + 随机基线对照），见 `ARCHIVE4.md` §37.1。
