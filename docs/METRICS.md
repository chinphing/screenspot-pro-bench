# 指标定义（METRICS）

## 一、命中率（Hit Rate）—— 第一层

```
命中 = 最终落点 (x,y) 在真值框 [x0,y0,x1,y1] 内
命中率 = 命中数 / (总数 − ERROR 数)
```

**⚠️ ERROR 会从分母剔除**——所以必须同时报 ERROR 数，否则稳定性问题被掩盖。

## 二、落点质量 —— 第二层（为什么必须看）

**命中只表示"落在框内"，不表示"落得准"。**

设想一个 200×200 的按钮：落在正中心和落在离边缘 1px 的角落，都算命中，
但对用户体验天差地别——前者点得中，后者可能点到相邻元素。

所以额外报告三个指标：

### ① 到中心距离

```
到中心(px) = 落点 → 真值框中心 的欧氏距离
到中心(%)  = 到中心(px) / 目标长边     ← 消除目标尺寸的影响，可跨样本比较
P75        = 75 分位（看长尾）
```

### ② 距边·半边长（居中度）

```
边距 = min(落点→框左边, 落点→框右边, 落点→框上边, 落点→框下边)
距边·半边长 = 边距 / (目标长边 / 2)
```

- `0` = 贴边，`1` = 正中心
- 与目标尺寸无关，可直接和随机基线比

### ③ 擦边率（Marginal Rate）

```
擦边 = 距边·半边长 < 0.25（即落点在框最外侧 25% 的环带里）
擦边率 = 擦边数 / 命中数
```

### ④ 失败距离

未命中样本到真值框中心的距离中位数。
**衡量"差多远"**——失败离得近说明机制方向对，只差精度；离得远说明找错了元素。

## 三、随机基线（判读的标尺）

假设落点在真值框内**均匀分布**，20 万次蒙特卡洛得到：

| 指标 | 随机基线 |
|---|---|
| 距边·半边长 中位 | **29%** |
| 擦边率 | **44%** |

**判读规则：**

| 表现 | 结论 |
|---|---|
| 距边 > 29% 且 擦边 < 44% | **优于随机** —— 落点有真实的居中倾向 |
| 距边 ≈ 29% 且 擦边 ≈ 44% | **≈随机** —— 命中基本靠运气，模型并没有"瞄准"能力 |
| 距边 < 29% 或 擦边 > 44% | **差于随机** —— 有系统性偏向 |

**实例（M1 上的实测）：**

| 方案 | 命中 | 距边 | 擦边 | 判读 |
|---|---|---|---|---|
| ZF·Qwen3.8 | 82% | 36%(+23%) | 30%(−31%) | 优于随机 |
| Z6·Qwen3.8 | 86% | **50%(+71%)** | 30%(−31%) | 优于随机（落点最居中）|
| ZF·DeepSeek | 74% | 36%(+23%) | 36%(−17%) | 优于随机 |
| **ZB·DeepSeek** | **61%** | **30%(+4%)** | **47%(+6%)** | **≈随机** ← 命中靠运气 |

**→ ZB 的 61% 看起来比随机猜高，但落点分布与随机无异，说明模型并没有真正定位。**
**→ 这就是"只看命中率"会踩的坑。**

## 四、其他指标

| 指标 | 说明 |
|---|---|
| 单次耗时 | 端到端平均秒数（含所有模型调用）|
| 调用次数 | 平均模型调用次数（含 L1），衡量成本 |
| ERROR | 异常终止数（超时/无输出/解析失败）|

## 五、实现

指标计算在 `bench/metrics.py`，报告用 `scripts/evaluate.py`：

```bash
python3 scripts/evaluate.py 'baselines/results/raw/*.jsonl' --labels 'A,B'
python3 scripts/evaluate.py <file> --by ui_type     # 按维度分组
```
