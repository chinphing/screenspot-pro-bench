## 一、⭐ 最终方案（本阶段结论）

**组合方案：单图 + 校验循环为主，非成功时自动兜底「17图选图 → 局部图上循环」**

```
阶段1  单图（2.5Mpx）→ L1 → 校验循环（画方块 → 验证 → 微调，最多3轮）
          │
          ├─ status == SUCCESS → 输出
          └─ 否则 → 阶段2/3 兜底
阶段2  17 张图（原图 + 4×4 局部图）→ 模型选图 + 给该图内 bbox
阶段3  在选中的那张局部图上跑校验循环 → 映射回原图
```

**驱动脚本**：`run_hybrid.sh`（端到端）

## 三、⭐ 关键发现

### ① 校验循环的"验证+微调"机制值 20 分

| 方案 | 仅"从零找" | 加校验循环 |
|---|---|---|
| DS 单图 | L1 **50%** | **70%**（+20） |
| Qwen 单图 | L1 **63%** | **81%**（+18） |

**→ 模型擅长"给我一个候选，我判断对不对、往哪挪"，不擅长"从零找"。**

### ② 给更多图反而更难找

| 方案 | 命中 |
|---|---|
| 单图 L1（从零找） | **50%** |
| 17 张图（从零找，选图+定位） | **36%** |

**→ 17 张图方案的两个核心假设都成立（选对图 86%、坐标系正确 89%），但"图内精确定位"这一环不行。**

### ③ 两条路线的失败原因完全不重叠

| 方案 | 失败原因 | 次数 |
|---|---|---|
| 单图+循环 | L1 偏太远，裁片够不到（±100px） | **18** |
| 局部图循环 | 17 图选错图（选错=必错） | **14** |

**→ 所以组合起来有增益，且**零误伤**。**

### ④ 单图循环的结构性限制

```python
img = Image.open(...)                     # 原图，只加载一次
for it in range(1, max_iter+1):
    cpx = int(max(crop_px, round(max(tw,th)*1.5)))   # 恒为 200px
    region = big.crop((x0, y0, x0+cpx, y0+cpx))      # 每轮都从原图裁
```

- 裁片**恒为 200px**（原图宽的 3.9–7.8%）
- **覆盖范围只有估计点 ±100px** → L1 误差超过 100px 就永远找不到
- 实测 18 次 TARGET_NOT_IN_CROP 的 L1 误差：中位 **270px**，17/18 超出覆盖范围
- **`--crop-ladder 200,400,800,1600` 参数已定义但代码从未使用**

### ⑤ 时间分解（智能体 v3o，平均 7.28s）

| 项目 | 平均 | 占比 |
|---|---|---|
| **模型调用** | **6.98s** | **96%** |
| 裁片准备（裁图+JPEG+base64） | 0.12s | 2% |
| 加载原图+首图准备 | 0.23s | 3% |
| 纯开销 | ~0s | ~0% |

**单次调用耗时随上下文增长**：第1轮 1200ms → 第2轮 1726ms → 第3轮 1932ms（**累积图片的代价**）。

### ⑥ 思考模式：对"看图定位"有害

| 场景 | 关思考 | 开思考 |
|---|---|---|
| DS 单图直接定位（无 tools） | **5/6** | 0/6（high） |
| DS 单图 + tools（智能体） | **63%** | 50%（low，且慢一倍） |
| DS 十图换算 | 3% | 50%（必需，但慢 20 倍） |

**→ 规律：任务核心是"看图定位"时思考有害；只有"多图换算"时思考必需。**

### ⑦ 模型对坐标系有强先验，别跟它对抗

| 坐标系约定 | 命中 |
|---|---|
| 强迫模型说"当前画面"坐标，代码反推 | **17%** |
| 让模型一直说"原图"坐标，代码不换算 | **60%** |

**→ 明确要求"用当前画面的坐标"后，模型仍有 17/28 次给原图坐标。**
**→ 但 17 张图方案里，模型**愿意**用所选图内的坐标（89/100）——因为那里没有"原图"这个强参照。**

## 四、DeepSeek 能力边界（汇总）

| 结论 | 数据 |
|---|---|
| 单图 token 上限 | **1008**（≈1300×1300），≥1.7Mpx 即吃满 |
| `detail` 字段 | `low` 生效；`original`/`high`/默认**完全相同** |
| 输出框大小 | 系统性偏小，宽高中位只有真值的 **0.7× / 0.6×** |
| 加复杂指令 | **有害**：加"完整框住元素"要求 → 60%→47% |
| 十图模式 | ❌ 补了像素尺寸+公式、开了思考也只打平，慢 20 倍 |
| 5 方向离散缩放 | ❌ 17%（"中"会切掉边缘目标，正确率仅 50%） |
| 自由给中心点 + 固定 1/2 裁剪 | ✅ 63%（智能体 v3o 最优配置） |
