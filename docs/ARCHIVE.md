> 归档时间：2026-10-15
> 目录：`benchmarks/screenspot_grid/`（自包含，未改动任何用户代码）
> 样本：20 条分层抽样（`/tmp/ids20.txt`）

## 一、当前最优流水线

```
L1：送图（缩放后）→ 描述提示词 → 输出归一化 bbox（0-1000）
  ↓
校验循环（最多 3 轮）：
  ① 在估计位置画方块标记 → 裁片（边长 = max(200, 目标长边×1.5)，上限 1600）
  ② 缩放后再画标记（标记宽 = 缩放后长边 × 48/1000）
  ③ 送校验模型，三步判定：
     一、目标在本裁片里吗？不在 → 退出
     二、方块在目标上吗？在 → 成功
     三、否则重新输出目标在本裁片里的 bbox → 重画标记 → 回到"二"
```

## 三、已确认的关键事实

### 1. 图片 token 上限
| 模型 | 上限 | 达到上限所需像素 |
|---|---|---|
| Qwen | ~2496 token ≈ 2.5 Mpx | 2.5 Mpx |
| **DeepSeek** | **1008 token ≈ 1300×1300** | **≥1.7 Mpx** |

**DeepSeek 的 token 曲线（实测）**：0.5M→316、0.8M→512、1.3M→778、**1.7M→1008（顶满）**、2.5M→1008、3.0M→1008。
**→ 送 1.7Mpx 和 2.5Mpx 等价；1.3Mpx 只有上限的 77%。**

### 2. `detail` 字段
`low`（512×512）有效；`original` / `high` / 默认**三者完全一样**，绕不过缩放。

### 3. 思考模式
| 场景 | 关思考 | 开思考 |
|---|---|---|
| DeepSeek 单图 | **5/6** ✅ | 0/6 ❌ |
| DeepSeek 十图 | 3% ❌ | 50% ✅ |

**→ 单图：思考有害；多图：思考必需但慢 20 倍。**

### 4. 失败模式
- **Qwen 双峰**：要么 5px、要么 400–700px（挑错相似元素）；循环救不回来（裁片里没目标）
- **DeepSeek 连续**：误差 20–300px，落在裁片可救范围内 → 循环能修（修好 10 次 / 改坏 1 次）
- **DeepSeek 的 `TARGET_NOT_IN_CROP` 是 Qwen 的 1.8 倍**（18 vs 10）——这是它落后的主要来源

### 5. 循环的收益（两者相同）
修好 10 次、改坏 1 次（100 次中）。

## 五、描述生成流水线（v7，当前版本）

```
① 外观：紧裁片（边长 = max(120, 目标长边×2.5)，画红框）→ 生成"外观 + 控件类型"（≤40 字）
② 方位：5×5 网格 → 纯计算
③ 锚点：整图 + 上下文裁片 + 【原分辨率横向条带】三张图 → 生成锚点（≤30 字）
    强制句式：禁止"目标在 X 的左侧/右侧"，必须写成"X 的某个部位"
    （例：✗ 右侧紧邻 utils.py 标签页  ✓ utils.py 标签文字右端的关闭按钮）
④ 不经校验（实测校验会把正确锚点改错）
```

**锚点句式修复的效果**：`vscode_macos_45` 从 0/5 → **5/5**（误差 445px → 2px）。

## 六、已排除的方案

| 方案 | 结论 |
|---|---|
| 原图 + 3×3 九宫格切图（10 张图） | ❌ 即使补上像素尺寸与换算公式、打开思考，也只打平单图，但慢 20 倍 |
| 网格线叠加 | ❌ 网格 200px 比模型自身精度（14px）粗得多；且遮挡 UI |
| qwen3.8-max 做锚点校验 | ❌ 会把正确锚点改错（4/5 vs 不校验 5/5） |
| DeepSeek 开思考做单图定位 | ❌ 5/6 → 0/6 |
